# Bundled Content Layout (iOS App Resources)

This document defines the **authoritative directory layout** for all scavenger hunt content bundled inside the iOS application.

The layout is a **contract** between:
- content authors
- validation and build scripts
- the iOS runtime loader

If this layout is respected, the app can load content deterministically and operate fully offline.

---

## 1. Design Goals

The bundled content layout must:

- Support offline gameplay
- Support multiple games and versions in parallel
- Allow fast lookup of node content by NFC tag ID
- Separate authored content from generated artifacts
- Be readable when inspecting the app bundle

---

## 2. Root Location

All bundled content lives under: ios-app/Resources/BundledContent/


This directory is included verbatim in the app bundle at build time.

**Do not edit files in this directory by hand.**  
It is generated by build scripts.

---

## 3. Top-Level Structure

BundledContent/
├─ README.md
├─ schemas/
│ └─ nfc-hunt-page.schema.json
└─ games/
└─ <GameName>/
└─ <GameVersion>/
├─ indexes/
│ └─ content-index.json
├─ nodes/
│ ├─ TAG001.node.json
│ ├─ TAG002.node.json
│ └─ TAG003.node.json
└─ media/
├─ P001/
├─ P002/
└─ P003/

---

## 4. Directory Responsibilities

### `schemas/`
- Contains JSON schemas used for validation
- Shared across all games and versions
- Must remain backward-compatible

Example: schemas/nfc-hunt-page.schema.json

---

### `games/`
Root directory for all bundled games.

Each game is isolated by name and version to allow:
- parallel development
- safe updates
- future expansions

---

### `<GameName>/`
Logical game identifier.

Examples:
- `FamilyHunt2026`
- `HalloweenHunt`
- `BirthdayQuest`

Must match:
- NFC payload `game.game_id`
- content index `game.gameName`

---

### `<GameVersion>/`
Specific content version.

Examples:
- `260113.01`
- `260214.02`

Must match:
- NFC payload `game.version`
- content index `game.gameVersion`

---

### `indexes/`
Contains index and metadata files generated by build scripts.

Required file: content-index.json

The app loads this file first to resolve NFC scans into node files.

---

### `nodes/`
Contains node JSON files.

Rules:
- One file per NFC tag
- Filename must match `tagRef.tagID`
- Schema validation is mandatory

Example: TAG001.node.json

---

### `media/`
Contains optional media assets referenced by node pages.

Rules:
- Organized by page or node ID
- Must not contain unused assets
- Media paths are relative to the version root

Example: media/P001/image1.png

---

## 5. Source vs Generated Content

| Location | Purpose |
|--------|--------|
| `data/` | Human-authored source content |
| `scripts/` | Validation and bundling tools |
| `BundledContent/` | Generated, app-ready artifacts |

**BundledContent is generated output.**

---

## 6. Validation Rules

A bundled content tree is valid if:

1. All required directories exist
2. `content-index.json` exists and parses
3. Every node file listed in the index exists
4. Every media directory listed in the index exists
5. Schema files are present
6. Folder names match declared game and version IDs

Failure of any rule invalidates the bundle.

---

## 7. Runtime Expectations (iOS App)

At runtime, the app will:

1. Load `BundledContent`
2. Select a game/version
3. Load `content-index.json`
4. Resolve NFC tag scans via the index
5. Load node files and media as needed
6. Operate entirely offline

The app must not attempt directory discovery or guessing.

---

## 8. Future Expansion

This layout supports:
- multiple games
- seasonal events
- localized content
- optional downloadable bundles (future)

Any breaking change to this layout requires:
- updated build scripts
- updated documentation
- updated runtime loader

---

## 9. Authoritative Rule

If content is not reachable through `content-index.json`, it does not exist.
